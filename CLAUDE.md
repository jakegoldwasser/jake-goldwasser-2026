## Luddite (`luddite/`)

Use these words, and only these, in the UI, in conversation and in commit messages (one word per idea, so a teacher always knows what a button means):

- **Writing session** — what a teacher opens for a class (never "room" or "assignment"; the code and the stored data still say `room`, and the API routes say `assignment`, which is left alone). Named for the work, never an auto date/time name. A session is **Happening now**, **Coming up** or **Past**, shown in those three groups on Home, and has a start time; it runs until the teacher ends it (the date and time are a stamp). Every session has an **Entry Phrase**; there are no permanent or standing rooms.
- **Casual session** — a writing session with no name, no class and no waiting room: one button on Home starts it now, and anyone who types its Entry Phrase is let straight in (`casual: true`). It is named by its prompt's first line once it has a prompt (e.g. "Write five favorite breakfast cereals", cut at about 60 characters), otherwise by its Entry Phrase (e.g. "Copper valley"), never "Casual session"; a name the teacher gives it (Rename, `titled: true`) wins over both; `titleOf` in the backend also shows the phrase for the first casual sessions, which were stored as "Casual session".
- **Class** — a list of email addresses a teacher makes by pasting or uploading (.csv/.txt). A session can be given a class: when it starts, everyone on the list who signs in is let in on their own (no waiting room). Anyone else can still type the Entry Phrase and wait in the waiting room.
- **Own time** — one student's own schedule inside a session: a different start, extra time (1.5×, 2×, or other), or both. The time picker follows the Horace Mann day: periods A–H in order, 45 minutes with 5 between, 8:25 to 3:15, break 10:00–10:20 (`DAY`, `PERIODS` in the page; the real day rotates the letters, so "Other time" covers that).
- **Hide names** — one button on the marking page only, that swaps the student's name for a stable alias ("Student K7Q"), on screen and in print. Drive copies still carry the real name, so "Open in Drive" is hidden while names are hidden.
- **Settings** — top right on teacher pages: what students get while writing (spellcheck, page lock, copy/paste, word count, auto hand-in), the owners' teacher list, and Account (display name, Google Drive, Write on my own, Sign out).
- **For you to write** — on Home, the sessions a teacher is in as a writer (another teacher gave one to a class they are on).
- **Entry Phrase** — the two words students type to join (never "code", "room code" or "code word"; `code` is fine inside the code).
- **Home** — the teacher's first page (not "Dashboard"). **Student work** is its list of everyone who has handed work in; a student's page is everything they've handed in. A past session's page lists its papers first.
- **Waiting room** — where students who aren't on the class list ask in. The teacher **lets them in**; a teacher **removes** someone.
- **Hand in / Handed in** — what a student does with their writing in a writing session (never "submit"). "Done" is only for writing on your own. A handed-in student is **locked** until the teacher **unlocks** them ("Unlock so they can write again").
- **Paper** — one handed-in piece of writing (not "piece" or "submission"; the Drive folder is literally named "Luddite submissions", which is left alone). **Mark up** is the verb; teachers write a **comment** in the margin, **cross out** words, **write in** words, draw an **arrow** between two points in the text (right-drag, or Control-drag on a Mac; it gets a numbered comment in the margin about the connection, numbered together with the comments), add an **end comment** and a **grade**. On the marking page the text is split into `.seg` spans; never reuse that class name for anything else (the choice-button rows are `.segctl`). The teacher's pen is green; red means locked or a warning. **Print all papers** is a button on a session's page (every paper handed in to it) and on a student's page (everything they've handed in); each paper prints marked up, one to a page.

**Luddite is its own product and must not be tied to Bookbug.** Jake does not want it connected to Bookbug in any way: no shared server, table, code, styles or sign-in state with `bookbug/`. Luddite's backend is `luddite-backend/index.mjs` (its own Lambda `luddite-api`, its own DynamoDB table `LudditeData`, its own `SESSION_SECRET`; setup in `luddite-backend/README.md`). Luddite's page look (light only; Jake wants it quiet and readable, with Bookbug's palette family as the benchmark): Rokkitt slab-serif wordmark, Literata headings and student writing, Bricolage Grotesque for everything else (three families, weights 400 and 600, one type scale), cream paper, umber ink, one moss-green main button, thin rounded outlines, explainers only on hover (`?` bubbles). Jake dislikes duplicate labels, decorative rules and buttons that a whole clickable card can replace. Make Luddite backend changes there and never in `cloud-sync-backend/` (Bookbug's). **Status:** done. The page's `API` constant points at the `luddite-api` Function URL, and Bookbug's Lambda no longer contains any Luddite code (the old `/luddite/*` routes were removed from `cloud-sync-backend/`). Luddite's data is in the `LudditeData` table; it was not copied from Bookbug's table unless `luddite-backend/migrate.mjs` was run.

**Luddite HM** is a Horace Mann copy of Luddite (BETA, @horacemann.org accounts only, its own Terms and Privacy) at jakegoldwasser-hm.github.io/luddite-hm/, in the repository `jakegoldwasser-hm/luddite-hm` (Jake's school GitHub account; local checkout `~/code/luddite-hm`). Every morning its GitHub Action fetches `luddite/index.html` from this repository's `main` and rebuilds the page with its `hm.sh`, so Luddite changes reach it within a day. `hm.sh` edits by pattern: the `<title>`, the `wordmark` headings, the `.wordmark { font-family: Rokkitt` style line, `../favicon.svg`, `../terms.html`, `/selection-highlight.js`, the Google sign-in options (`use_fedcm_for_prompt: true, itp_support: true`), `me = data.luddite;` in `start()`, and `</body>` (where it adds `hm-admin.js`). If a Luddite change removes one of those, the HM sync fails and the HM site stays as it was, so update `hm.sh` there too. It uses the same `luddite-api` server and data; the Function URL's CORS and the Google client's JavaScript origins both list `https://jakegoldwasser-hm.github.io`. **Luddite HM administrators** (HM only): Horace Mann's administration can read everything HM teachers and students write, from the HM repository's `admin.html`. The server side is `routeHmAdmin` (`/luddite/admin/*`) in `luddite-backend/index.mjs`, fenced to requests from `https://jakegoldwasser-hm.github.io`, to administrators, and to teachers with @horacemann.org addresses, so regular Luddite never shows or reaches it; it needs `dynamodb:Scan`. Don't remove that fence, and don't build admin features into `luddite/index.html`. **Jake must not be able to read Luddite HM's data:** he is only an admin *manager* (`HM_ADMIN_MANAGERS`: adds and removes administrators, sees nothing), and the owner role's reach into other teachers' work skips @horacemann.org teachers (`ownerMayOpen`). Keep it that way. This Mac's saved GitHub sign-in is the personal account, so changes to that repository go up through GitHub's web upload in Chrome (signed in as jakegoldwasser-hm).

## Bookbug (`bookbug/`)

- The app's name is **Bookbug** — one capital B. Never "BookBug", "Book Bug", or "BookLouse". The lowercase `bookbug` wordmark in the page header is a logo and stays lowercase. This applies everywhere: UI text, `<title>`, comments, commit messages, docs.
- Use these terms consistently in the UI and in conversation: **book title**, **section title**, and each book type's own word for its parts — **poem** in a poetry collection, **chapter**/**part** in a novel, **essay**/**section** in essays, **scene**/**act** in a screenplay or play (never "heading", "chapbook", or "body text"; "entry" only in code and in text that covers every type at once). UI strings take these from `TEXT_FORMS` (`formNouns()`, `data-noun` spans filled by `applyFormWording`), never hard-coded. Internal identifiers such as `state.poems`, `chapbookId`, and the `chapbookbuilder` cloud key are legacy names; leave them alone rather than renaming stored data.
- A book is either on Home (the book grid, formerly called "My Books"), archived, or deleted. Delete is only offered from the archive, except for a text book's entries (poems, chapters, essays, scenes), whose ⋯ menu also has **Delete…**: it skips the archive, and Restore puts the entry back at its old place in the book (`from: 'book'`, `at`). **Deleting is recoverable for 7 days** (`RECOVER_DAYS`; entries in `deletedPoems` for 30, `ENTRY_RECOVER_DAYS`): a deleted book goes to **Recently deleted** at the bottom of Home (`recentlyDeleted`, synced; the Lambda merges it by id and drops entries past 7 days or since restored), and within a book, deleted archived poems/chapters (`state.deletedPoems`), spreads deleted or emptied from the archive (picture book `deleted`) and emptied cartoons (cartoon book `deleted`) show in a Recently deleted part of that book's archive panel. Restore puts it back where it was deleted from (the archive, or a spread's old place). Confirmations for these say it can be restored, on a red Delete button.
- **Archive, don't delete.** Removing anything that has content in it (a book, poem/chapter/essay/scene, section/part/act, spread, picture-book text box or illustration, or a cleared spread's contents) sends it to its archive, where it can be restored. The only exception: something with no information at all (empty entry, untitled empty section, empty spread, empty text box, a book with nothing of the author's in it) is removed outright, skipping the archive. The untouched sample a new novel, essay collection, screenplay or play starts with doesn't count as content, and an import replaces it. A button labeled "Archive" only ever archives something. Each archive (a book's, a picture book's, a cartoon book's, Home's) is its own panel, shown only while it holds something, and opened or closed by the Show / Hide on that panel (`syncArchivePanel`); nothing elsewhere toggles it.
- Bookbug has seven **book types**: **poetry collections** (`form: 'collection'`; poems, each starting on a page of its own), **novels** (chapters and parts), **essay collections** (essays and sections), **screenplays** and **stage plays** (scenes and acts; see below), **picture books**, and **cartoon batches** (the UI says "cartoon batch", never "cartoon book"; code and stored data still say `cartoonBooks`, `cb…`; a drawing and a caption per page, captions set New Yorker style in Caslon italic; no cover or title page, since a cartoon book is a batch; `cbLibrary`, its own editor, synced as `cartoonBooks`; its import dialog takes a PDF, chosen photos, or photos taken live with the camera, `getUserMedia`, as many as wanted until Done; on a page of doodles, each one with a loop drawn round it (pen or light pencil; loops may touch) comes in as its own cartoon with the loop erased, `scanFindCircles`, shown as numbered boxes to tap out or drag in, erring toward finding too many; a loop round several loops, like the paper's own edge in a photo, is offered left out; a printed cartoon's heavy box line is whited out, `scanStripFrame`; a page with no loops comes in whole. Each imported cartoon keeps its cleaned page as an image (`images[id].page`, not preloaded) and where it was cut from (`crop`), so **Frame** on a cartoon (or ⋯ › Frame the drawing…) can move it or zoom out on the page, `cbOpenFrame`). The first five share the collection editor, set apart by `state.form` (`TEXT_FORMS` holds each one's defaults and nouns). In a novel a blank chapter title shows as "Chapter N" and a blank part "Part One" by position; in a play, "Scene N" (restarting each act) and "Act One". Novels and essays default to book-style prose paragraphs (`paragraphs: 'indent'`: a half-inch first-line indent, the same as a Tab, shown in the editor too via `tagProseLines`; a line of `***` is a scene break). Home shows a shelf only for each type the person has (unarchived) books of ("Poetry collections", "Novels", "Essay collections", "Picture books", each shelf color-coded in its editor colorway and showing titles in its own cover typeface; **New book** — one big blank white page at the top left of Home, Docs style, plus one entry at the top of the Home menu, never one per type — opens one dialog: a title, then which book type, with a picture book's pages/shape/front matter in the same dialog), so someone making only one kind never sees the other. The shelves' order is the person's: drag a shelf by its grip (pointer events, so phones too; arrow keys on the focused grip), stored with `homeForms` and followed by the Home menu. A book's title shows only on its cover on Home, not repeated under it. Preferences are grouped: the text book types share one group, picture books have their own; every group for a type on Home is shown, the one for the book you're in first and open, the others folded under their labels (all open on Home). The text group's **Tab indent** (¼–1 in, default ½ in like Docs/Word; `prefs.tabIndentPt` → `TAB_STOP_PT`) sets both a Tab and a prose paragraph's first-line indent, in the editor and in print. Verse lines' hanging indent uses `text-indent: … hanging`, never padding plus a negative indent (that pulled every tab stop back).
- A picture book is laid out by the **spread**: page 1 alone, numbered spreads (a verso and a recto page), and the last page alone, so n spreads make 2n − 2 pages. Pages can have a **role** (title page, copyright, endpaper, pastedown…). Spreads hold free-placed **text boxes** and **illustrations** (the UI says "illustration", never "picture", for the art; code still says `image`/`pic`). Each spread's notes are **illustration notes**. Text boxes can bold or italicize single words: the text holds the book editor's `**bold**` / `*italic*` markers, edited in rich fields (`pbRichField`, a contenteditable with a textarea-like `value`), set word by word everywhere it's drawn (`pbWrapRich`, `pbRunFont`) and as separate runs in PowerPoint; B / I (or Cmd/Ctrl+B, I) style the selected words, or the whole box with nothing selected. Title, author and byline boxes stay plain. A spread's ⋯ menu has **Delete…**, which skips the archive: immediately if the spread is empty, otherwise after a confirmation. Exports: digital dummy, printable dummy, PowerPoint. Story Plotter (`/storyplotter/`) isn't in the site nav any more; it's reached from the **Story Plotter** panel in a picture book's tools column. It is the old Dummy Builder folded into Bookbug; don't bring Dummy Builder back as a separate tool.
- A picture book has three views: **Text** (the default: each page's words in large fields), **Spread** (as printed; double-click a page to add a bottom-center text box; click a box to select it, click again to edit it in a larger pop-up) and **Thumbnail**. In Text view each text box has a grip to drag it to any page in the book (pointer events, so fingers work too; `pbMoveTextToPage`), and two boxes on the same page can be **merged** (Merge on the line between them, or in Spread view's quick bar; `pbMergeText`) -- the lower box's words join the upper one's on a new line. Title, author and byline boxes aren't merged. On touch screens, swiping a Text view box left removes it (to the archive if it has words; `pbArchiveTextBox`), with Undo in the toast. New story boxes start centered (`pbNewStoryBox`); alignment is per box, under Formatting > Alignment. Formatting, Front and Back Matter and Export are in every view; outside Text view they start folded. Formatting opens on **Whole book**; a switch at its top (`pbFmtScope`) goes to **This text box** / **This illustration** once one is selected, and back to the book when nothing is. **Front and Back Matter** (`renderPbMatter`) picks a standard layout (`PB_LAYOUTS`, applied by `pbApplyLayout`), sets each front and back page's role, and edits the dedication and copyright wording. Sliders offer about ten steps each (a text box is at most a page wide). On phones (≤ 860px) the tools column sits below the book, so a **Formatting** button at the top of every editor (`.fmt-jump`, in place of Hide tools) opens that panel and scrolls to it. Only the first three and last two pages can take a non-story role (pp. 4–5 and the third-last only when they follow endpapers); `pbRoleOptions` decides what each page may be from the page before it, and `pbApplyRole` lays out that role's usual text.
- **Scripts** (`SCRIPT_SPECS`, `scriptElements`, `layoutScript`) are typed in plain text with Fountain's conventions (capitals line over a speech = character, `(parenthetical)`, INT./EXT. heading, `TO:` transition, `>centered<`, `! @ . >` to force) and set on the industry page: US Letter, Courier 12 at 6 lines/inch (54 per page), 1.5 in left margin, page numbers top right from page 2 with a period, a title page (no cover), no folded booklet export. Screenplay: a scene's title is its slugline; scenes run on (the run's first scene holds the pages, the rest point at it with `host`/`hostPage`); speeches break with (MORE)/(CONT'D). Play: each scene starts a page under its act and scene; names centered, directions indented and italic. The editor tags each line (`data-sel`) so it sits where it prints. A script's scene title alignment is fixed by format (screenplay left, play centered; `titleAlignFor`). In a play, Enter on an empty line steps it along (`playEnter`): under a speech, a stage direction; then a character name; then the likeliest speaker filled in (`likelyNextSpeaker`). A play has a **character list** in Front and Back Matter (`castList`, `castPagePlan`; `includeCast`, `castHeading`, `castNotes`, `castHidden`), a page after the title page. With Front and Back Matter open on a page left out of the book, the preview still shows that page, marked as not included.
- **Importing many files at once** (`importFileBatch`): a Drive folder or several picked files (`openDriveFilesPicker`, multiselect Picker; a folder's contents are listed through the Drive API, and if `drive.file` hides them the person is told to open the folder and select the files), or PDFs/text from the computer. Files go in file-name order (numeric-aware), each parsed on its own; PDFs are read with pdf.js from cdnjs, loaded on first use (`pdfToDocText`: lines rebuilt from positions, bigger gaps = stanza breaks, larger type = titles, lone page numbers dropped). A file with no title of its own takes a short first line standing alone, else its file name minus any leading number (`withFileTitle`, `fileTitle`).
- Each book type has its own colorway in its editor and on its Home shelf: light green poetry, terracotta novels, plum essays, goldenrod screenplays, verdigris plays, slate-blue picture books (`body.view-pb`), newsprint/umber cartoons (`body.view-cb`). Home itself stays on the base beige card.
- **Tiers** (poetry collections only): a poem can be marked with one of the person's own named tiers (default Finished, Needs revision, Draft) from the pill beside its ⋯. The tiers are named, added, removed or switched off under Preferences ("Mark poems by tier"); they sync with the account as `poemTiers` (`{ on, at, tiers: [{ id, name }] }`, newer `at` wins), and each poem keeps its tier's id in `poem.tier`. Removing a tier leaves its poems with none, with Undo in the toast. A poetry collection also has a quiet **+ Add poem** above the list (`addPoemTopBtn`) matching the one below it.
- In a text book's list, hovering a row (Title View, Tier View) shows that entry in the preview and a click opens it. A **Find a poem** box above the list (`entrySearch`, wording from `formNouns`) filters to entries whose title or text has every typed word; the writer's previous/next follow the filtered, current view's order (`viewOrder`). In scripts a likely character name shows faintly where a name goes (`updateNameSuggest`); the Right arrow fills it in.
- `window.bookbugMarkdown(titleOrId)` is a read-only hook on the page (the Export as Markdown text of a book found by id, title or title prefix, plus whether the page has synced). Jake's weekly "Desert News" backup email (a scheduled task in the Claude app) reads his book through it in Chrome; keep its name and return shape.
- Picture books sync as `pictureBooks` / `pictureBookTrash` (plus `homeForms`) under the same `chapbookbuilder` cloud key. Their pictures are stored apart, one per item in the `BookbugImages` DynamoDB table via the Lambda's `?image=` routes, and cached in the browser's IndexedDB.
