# jake-goldwasser.com

## Bookbug (`bookbug/`)

- The app's name is **Bookbug** — one capital B. Never "BookBug", "Book Bug", or "BookLouse". The lowercase `bookbug` wordmark in the page header is a logo and stays lowercase. This applies everywhere: UI text, `<title>`, comments, commit messages, docs.
- Use these terms consistently in the UI and in conversation: **book title**, **section title**, **entry title**, **entry** (not "poem", "heading", "chapbook", "collection", "body text", or "title page"). Internal identifiers such as `state.poems`, `chapbookId`, and the `chapbookbuilder` cloud key are legacy names; leave them alone rather than renaming stored data.
- A book is either on Home (the book grid, formerly called "My Books"), archived, or permanently deleted. There is no trash. Permanent delete is only offered from the archive.
- **Archive, don't delete.** Removing anything that has content in it (a book, entry/chapter/essay, section, spread, picture-book text box or picture, or a cleared spread's contents) sends it to its archive, where it can be restored. The only exception: something with no information at all (empty entry, untitled empty section, empty spread, empty text box, a book with nothing of the author's in it) is removed outright, skipping the archive. The untouched Lorem Ipsum sample a new novel/essay collection starts with doesn't count as content.
- Bookbug has five **book types**: **poetry collections** (`form: 'collection'`; entries, each starting on a page of its own), **novels** (chapters and parts), **essay collections** (essays and sections), **picture books**, and **cartoon books** (a drawing and a caption per page, captions set New Yorker style in Caslon; `cbLibrary`, its own editor, synced as `cartoonBooks`). The first three share the collection editor, set apart by `state.form` (`TEXT_FORMS` holds each one's defaults and nouns; in UI text use that type's own words — entry/chapter/essay, section/part). In a novel a blank chapter title shows as "Chapter N" by position. Novels and essays default to book-style prose paragraphs (`paragraphs: 'indent'`; a line of `***` is a scene break). Home shows a shelf only for each type the person has (unarchived) books of ("Poetry collections", "Novels", "Essay collections", "Picture books", each shelf color-coded in its editor colorway and showing titles in its own cover typeface; **Add book type** starts a book of a type not yet on Home), so someone making only one kind never sees the other. Preferences are grouped: the text book types share one group, picture books have their own.
- A picture book is laid out by the **spread**: page 1 alone, numbered spreads (a verso and a recto page), and the last page alone, so n spreads make 2n − 2 pages. Pages can have a **role** (title page, copyright, endpaper, pastedown…). Spreads hold free-placed **text boxes** and **pictures**. Exports: digital dummy, printable dummy, PowerPoint. It is the old Dummy Builder folded into Bookbug; don't bring Dummy Builder back as a separate tool.
- A picture book has three views: **Text** (the default: each page's words in large fields, with Formatting and Export beside it), **Spread** (as printed; double-click a page to add text, click a box to edit it in a larger pop-up) and **Thumbnail**. Only the first three and last two pages can take a non-story role (pp. 4–5 and the third-last only when they follow endpapers); `pbRoleOptions` decides what each page may be from the page before it, and `pbApplyRole` lays out that role's usual text.
- Each book type has its own colorway in its editor and on its Home shelf: light green poetry, terracotta novels, plum essays, slate-blue picture books (`body.view-pb`), newsprint/umber cartoons (`body.view-cb`). Home itself stays on the base beige card.
- Picture books sync as `pictureBooks` / `pictureBookTrash` (plus `homeForms`) under the same `chapbookbuilder` cloud key. Their pictures are stored apart, one per item in the `BookbugImages` DynamoDB table via the Lambda's `?image=` routes, and cached in the browser's IndexedDB.
