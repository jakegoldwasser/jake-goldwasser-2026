## Bookbug (`bookbug/`)

- The app's name is **Bookbug** — one capital B. Never "BookBug", "Book Bug", or "BookLouse". The lowercase `bookbug` wordmark in the page header is a logo and stays lowercase. This applies everywhere: UI text, `<title>`, comments, commit messages, docs.
- Use these terms consistently in the UI and in conversation: **book title**, **section title**, and each book type's own word for its parts — **poem** in a poetry collection, **chapter**/**part** in a novel, **essay**/**section** in essays, **scene**/**act** in a screenplay or play (never "heading", "chapbook", or "body text"; "entry" only in code and in text that covers every type at once). UI strings take these from `TEXT_FORMS` (`formNouns()`, `data-noun` spans filled by `applyFormWording`), never hard-coded. Internal identifiers such as `state.poems`, `chapbookId`, and the `chapbookbuilder` cloud key are legacy names; leave them alone rather than renaming stored data.
- A book is either on Home (the book grid, formerly called "My Books"), archived, or permanently deleted. There is no trash. Permanent delete is only offered from the archive.
- **Archive, don't delete.** Removing anything that has content in it (a book, poem/chapter/essay/scene, section/part/act, spread, picture-book text box or illustration, or a cleared spread's contents) sends it to its archive, where it can be restored. The only exception: something with no information at all (empty entry, untitled empty section, empty spread, empty text box, a book with nothing of the author's in it) is removed outright, skipping the archive. The untouched sample a new novel, essay collection, screenplay or play starts with doesn't count as content, and an import replaces it.
- Bookbug has seven **book types**: **poetry collections** (`form: 'collection'`; poems, each starting on a page of its own), **novels** (chapters and parts), **essay collections** (essays and sections), **screenplays** and **stage plays** (scenes and acts; see below), **picture books**, and **cartoon books** (a drawing and a caption per page, captions set New Yorker style in Caslon; `cbLibrary`, its own editor, synced as `cartoonBooks`). The first five share the collection editor, set apart by `state.form` (`TEXT_FORMS` holds each one's defaults and nouns). In a novel a blank chapter title shows as "Chapter N" and a blank part "Part One" by position; in a play, "Scene N" (restarting each act) and "Act One". Novels and essays default to book-style prose paragraphs (`paragraphs: 'indent'`; a line of `***` is a scene break). Home shows a shelf only for each type the person has (unarchived) books of ("Poetry collections", "Novels", "Essay collections", "Picture books", each shelf color-coded in its editor colorway and showing titles in its own cover typeface; **New book** — one button on Home and at the top of the Home menu, never one per type — opens one dialog: a title, then which book type, with a picture book's pages/shape/front matter in the same dialog), so someone making only one kind never sees the other. Preferences are grouped: the text book types share one group, picture books have their own; every group for a type on Home is shown, the one for the book you're in first.
- A picture book is laid out by the **spread**: page 1 alone, numbered spreads (a verso and a recto page), and the last page alone, so n spreads make 2n − 2 pages. Pages can have a **role** (title page, copyright, endpaper, pastedown…). Spreads hold free-placed **text boxes** and **illustrations** (the UI says "illustration", never "picture", for the art; code still says `image`/`pic`). Each spread's notes are **illustration notes**. Exports: digital dummy, printable dummy, PowerPoint. It is the old Dummy Builder folded into Bookbug; don't bring Dummy Builder back as a separate tool.
- A picture book has three views: **Text** (the default: each page's words in large fields), **Spread** (as printed; double-click a page to add a bottom-center text box; click a box to select it, click again to edit it in a larger pop-up) and **Thumbnail**. In Text view each text box has a grip to drag it to any page in the book (pointer events, so fingers work too; `pbMoveTextToPage`), and two boxes on the same page can be **merged** (Merge on the line between them, or in Spread view's quick bar; `pbMergeText`) -- the lower box's words join the upper one's on a new line. Title, author and byline boxes aren't merged. On touch screens, swiping a Text view box left removes it (to the archive if it has words; `pbArchiveTextBox`), with Undo in the toast. New story boxes start centered (`pbNewStoryBox`); alignment is per box, under Formatting > Alignment. Formatting and Export are in every view; outside Text view they start folded. On phones (≤ 860px) the tools column sits below the book, so a **Formatting** button at the top of every editor (`.fmt-jump`, in place of Hide tools) opens that panel and scrolls to it. Only the first three and last two pages can take a non-story role (pp. 4–5 and the third-last only when they follow endpapers); `pbRoleOptions` decides what each page may be from the page before it, and `pbApplyRole` lays out that role's usual text.
- **Scripts** (`SCRIPT_SPECS`, `scriptElements`, `layoutScript`) are typed in plain text with Fountain's conventions (capitals line over a speech = character, `(parenthetical)`, INT./EXT. heading, `TO:` transition, `>centered<`, `! @ . >` to force) and set on the industry page: US Letter, Courier 12 at 6 lines/inch (54 per page), 1.5 in left margin, page numbers top right from page 2 with a period, a title page (no cover), no folded booklet export. Screenplay: a scene's title is its slugline; scenes run on (the run's first scene holds the pages, the rest point at it with `host`/`hostPage`); speeches break with (MORE)/(CONT'D). Play: each scene starts a page under its act and scene; names centered, directions indented and italic. The editor tags each line (`data-sel`) so it sits where it prints.
- Each book type has its own colorway in its editor and on its Home shelf: light green poetry, terracotta novels, plum essays, goldenrod screenplays, verdigris plays, slate-blue picture books (`body.view-pb`), newsprint/umber cartoons (`body.view-cb`). Home itself stays on the base beige card.
- Picture books sync as `pictureBooks` / `pictureBookTrash` (plus `homeForms`) under the same `chapbookbuilder` cloud key. Their pictures are stored apart, one per item in the `BookbugImages` DynamoDB table via the Lambda's `?image=` routes, and cached in the browser's IndexedDB.
